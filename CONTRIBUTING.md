# Contributing to ezmock

Thank you for improving ezmock.

1. Open an issue in the **affected SDK or specification** repository before large breaking changes.
2. Behavior changes start with `ezmock-spec`; update the schema, examples, conformance vectors and version notes.
3. Platform implementations should implement the same behavior while remaining idiomatic to their ecosystems.
4. Add tests and update the example application for any new public feature.
5. Submit focused pull requests with description, test evidence and associated spec version.
6. By submitting your work you agree it is licensed under the relevant repository's Apache-2.0 license. A DCO or CLA may be introduced following project governance review; it is not currently imposed by this starter.

Do not submit API keys, production data, personally identifying fixture data, or company secrets. Use fictional test-domain URLs and data.
